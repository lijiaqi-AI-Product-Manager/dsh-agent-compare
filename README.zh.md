# AgentCompare

[English](README.md) | 中文

**同一需求，两版真跑，盲选再揭晓。**

AgentCompare 是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）插件。它把一个前端任务交给两个独立的 Agent，在两份隔离的项目副本里各做一版；然后**真的安装依赖、启动两个应用**，对两边跑**同一套验收**。你先亲手操作两份真实页面并做出选择，之后才揭晓各自用的策略（或模型）。最后把选中的版本**安全采用**回你的项目。

> 状态：**0.1.0-alpha，尚未发布到 npm**。下方「已验证」只列出实际跑过的内容。

## 适合什么任务

适合界面和交互类任务，也就是好坏要靠人体验、测试判不出来的那种：落地页、仪表盘布局、搜索/筛选交互、组件重设计。
答案唯一的修 bug 或重构，用单个 Agent 加测试更合适。

## 它替你做掉的那部分

自己开两个会话也能让模型写两版，真正麻烦的是后面这些：

- 两份代码要从**同一基线**出发，包括你还没提交的改动，同时你的 index 和文件一点都不能动；
- 两边各装一份依赖、各占一个端口，**同时跑起来**；
- 用**同一套、事先固定的**验收比较，不能让各自写的测试各说各话；
- 选完以后合回主仓库时，不覆盖你在这期间做的修改。

## 工作流程

1. 记录基线：用私有临时 index 给当前工作区拍快照（含未提交和未跟踪文件，不含被忽略的文件），不修改你的 index 和文件。
2. 为两个候选各建一个 `git worktree --detach`，不建分支。
3. 每个候选作为 DSH 的 `spawn` 子 Agent 运行，`cwd` 设为它自己的 worktree。
4. 冻结改动：生成完整的二进制补丁，记录 SHA-256，并始终排除 `node_modules`。
5. 用锁文件安装依赖（`npm ci` / `pnpm --frozen-lockfile`），在独立端口上启动 Vite，并确认 HTTP 真的有响应。
6. 跑统一验收：`typecheck` / `lint` / `build` / `test` 脚本，外加无头浏览器检查（页面可加载、无控制台错误、截图；优先用系统自带的 Edge/Chrome）。
7. 盲选面板：左右两个 iframe 展示真实运行的应用，只标 A/B。选完才揭晓策略，并显示「程序验收倾向」与「你的选择」是否一致。
8. 采用：
   - **写入工作区**（默认）：先确认候选触及的文件自基线以来没被你改过，再按仓库自己的换行和过滤设置写入。写入后逐文件核对，确认与验收过的版本一致；不提交，不改 index。失败时自动回滚到采用前的快照。之后也可以手动撤销（前提是你没再改过这些文件）。
   - **新建分支**：不切换、也不修改当前 checkout。

## 已验证（2026-11-01，Windows 11，Node 24，Git 2.53）

- 19 个单元/集成测试（真实 git，临时目录路径带空格）覆盖：快照不改动用户 index；新增、删除、二进制和嵌套新文件；目标文件变化时拒绝采用且一个字节都不写；非重叠变化下正常采用；撤销；分支模式；CRLF 仓库。
- `node scripts/smoke.mjs`：用脚本代替模型，其余全部是真实执行。两份 Vite 应用约 16–22 秒内都可交互，统一验收、浏览器检查、采用都跑通，用户未提交的文件保持不变，清理后没有遗留的开发服务器。
- `--break B`：B 的类型错误被 `typecheck` 抓到，而 `vite build` 仍然通过。这说明「能构建」和「通过检查」是不同层次的结果。
- 用 `npm pack` 产物装进全新的隔离 profile（`dsh plugin --profile <name> add <tgz>`），在 DSH 0.2.1-rc.3 上组合成功。

## 尚未验证（不要当成已支持）

- 在 DSH 桌面版和 Web UI 里实际加载面板，以及 iframe 在 `dsh-app://` 页面中的表现。打不开时可以用面板提供的「在浏览器中打开」。
- 真实模型跑完整一轮的耗时与成功率。
- Windows 沙箱对 worktree 之外写入的实际拦截效果（DSH 官方标注为 partial）。
- macOS / Linux。

## 已知限制

- 只支持 Vite 项目和 npm / pnpm / yarn 锁文件；必须是至少有一次提交的 Git 仓库。
- 用量：DSH 0.2.1 的子 Agent 结果不带 token 用量，所以显示为「未知」，不会显示成 0。
- 隔离范围：代码隔离靠 worktree，写入边界靠 DSH 沙箱；网络和进程**不隔离**，我们启动的开发服务器也不受沙箱约束。
- npm 11 默认会拦截安装脚本（`allowScripts`），依赖原生安装脚本的项目可能需要你先在项目里批准。
