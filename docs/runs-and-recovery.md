# 运行记录与恢复

构建输出按基线的 Git 忽略规则处理，不再一概排除名为 `dist` 的目录。项目使用自定义 Vite `build.outDir` 时，先将输出目录加入 `.gitignore`，再开始比较；Vite 配置和 `.gitignore` 会随基线绑定，包括已纳入快照的未提交编辑。已被 Git 跟踪的文件即使位于忽略目录内，也会继续检查。验收期间出现未忽略的新文件或已跟踪文件变化，会阻止采用，需要修正配置后开始新的比较；不会改写当前验收或悄悄删除这些文件。此项更严格的源码漂移检查尚未发布。

主分支新增的停止预演、跨对话操作确认及当前状态同步，尚未包含在 npm 1.0.1 中。[本次状态同步记录](https://github.com/lijiaqi-AI-Product-Manager/dsh-agent-compare/blob/main/docs/measurements/current-context-2026-11-05.json)区分安装源码、实际上下文与模型回答；两次请求来自同一个受控比较，并不代表所有模型的可靠率。

主对话组装模型上下文时，会附上该对话最近更新的比较状态，包含运行编号、记录修订、选择、采用方式与采用状态。它会明确覆盖同一次比较的旧状态说明，区分「已选择」「写入工作区」「另存分支」和「已撤销」。历史说明仍保留；候选对话和没有实际请求的空闲对话不附加这份状态，读取失败时会注明当前状态未知。

历史可查看全部对话。选择、采用、撤销、停止、重新验收、重新打开预览或释放副本时，会先由宿主解析当前对话；操作其他对话的比较或无法确认所属对话的旧记录，需要核对项目、运行编号并确认本次操作。确认不会绕过宿主权限、运行归属锁或文件完整性核验。按 Esc 可取消确认并留在历史窗口；每项操作分别确认。

采用前若需要合并你后续的编辑，会在副本中预演。原对话的卡片可点「停止采用预演」，等待本次进程及子进程退出后回到已揭晓状态；候选源码、补丁与运行记录继续保留，可重新审查采用。若进程退出无法确认，会保留预演副本并阻止再次采用。开始保留原始文件和写入以后，停止入口会消失，需等待交接与核验完成。

需要整理依赖和缓存时，使用[副本空间与确认清理](copy-cleanup.md)。此入口保留源码补丁、Git 引用及撤销原件，不自动过期删除记录。

新建和已有对话的右上角均提供「比较记录」与「使用教程」，直接打开历史或指南，并保留宿主原有的角落控件。预览已停止时显示明确状态和已有截图；副本仍在则可以重新打开预览。

重启后打开旧对话的比较设置，会通过 DSH 的会话域恢复原会话，不发送模型消息，也不另建对话。并发读取共享恢复过程；取消一条请求不会取消另一条请求，仍遵守宿主的会话权限。

比较记录默认浏览全部对话，也可切换到当前对话。按需求、项目或运行编号搜索，每页显示 30 条并支持翻页；原始记录持续保留。列表中的旧版记录只读。安装后若界面提示服务端尚未更新，重启 DSH 再使用新控件。

格式不完整、不兼容、无法读取或超过 16 MiB 的记录会标为「需处理」，说明原因并保留原文件，不阻塞其它正常记录。可勾选「只看需处理」查找；不会依据这些记录操作项目文件或进程，过期更新也不会覆盖损坏记录。

正在管理比较的宿主持有运行归属。其它同版本宿主共享本地记录时，仍可查看历史、源码改动和真实预览；选择、停止、采用和清理保持只读，直到原宿主关闭，界面会自动刷新归属。正常关闭会先等待已接受的工作退出；进程崩溃后，SQLite 连接锁由系统释放，新宿主再恢复孤立记录。采用、撤销与写入恢复还在 Git 公共目录中共享仓库锁，覆盖不同插件数据目录和链接工作区。

已经打开的另一个宿主，在打开、刷新记录或取得操作归属时也会恢复孤立记录：生成标为中断，核验后清除已停止预览的旧地址，写入中断则显示采用恢复操作；无法确认归属或清理状态的资源会保留并说明原因。仍有活跃所有者的比较和无归属凭据的旧记录保持原样。卡片同时核对运行编号和修订，延迟响应不会把已选择或已采用的结果改回旧状态。状态工具只允许主对话调用，候选不能借它恢复其它比较的资源。

升级前先完成或清理活动比较，并关闭所有旧版本实例；不支持不同插件版本并发修改同一份记录。新记录带协调标记，alpha.9 会将它保留为不可操作的只读记录，更早版本不识别这条边界。旧记录若缺少归属凭据且仍可能有活动资源，当前版本只提供查看，不推断任务已经退出。旧 `.lock` 目录会保留并阻止对应操作，需要在旧实例停止后检查。SQLite 锁文件必须保留在本地文件系统上，暂不支持网络共享目录锁。

比较任务通过宿主命令执行器进入会话日志，卡片按运行编号读取同一份持久记录。结果、选择、采用或撤销会形成模型可读说明；会话暂不可用或注入失败时会重试，并对会话历史和待处理消息去重。说明明确标出目标仓库，避免把示例结果误认为原项目的改动。

直接采用会先保留实际原始文件，再交接候选；交接遇到新编辑或同路径新文件时会停止，保留双方内容。结果中的「查看保留内容的位置」列出项目内自忽略的 `.agent-compare-transfer-*` 目录。目录含原始项目内容和日志，不会随副本或预览清理；恢复结束前请勿删除，也不要把它作为公开演示素材上传。

中断可能发生在采用、撤销或旧记录恢复中。界面会区别「恢复到采用前」和「回退未完成操作」：后者回到上次撤销或恢复开始前，并可能仍需再恢复原采用。冲突路径不会被自动覆盖；请核对当前文件及保留内容后再处理。旧记录首次撤销或恢复也使用新的文件交接方式，但无法补回旧版本未保留的原始字节。

直接写回只支持普通文件、最多 10,000 个路径及合计 128 MiB 的原始与候选内容，并要求本地文件系统支持硬链接。限制不满足时会停止写回，可另存分支审查；不会回退到覆盖式写入。更新界面若仍连接旧后台，会阻止直接采用并提示重启 DSH。

`/ab <需求>` 保留为可选快捷方式。常用设置均在输入框上方完成。

Windows 进程检查和终止辅助命令都有等待上限。无法确认整个任务进程树已停止时，记录会明确说明，保留候选或采用预演副本，并阻止对该副本重新验收或重复采用；重启也不会将它当成已经停止。请先检查该任务及其子进程，再按提示手动清理保留的副本。其他已完成候选仍可查看和选择。

尚未选择结果时，安装、验收或预览阶段失败／中断的已封存候选可点「重新验收 A/B」。它复用原提交、补丁与验收定义，不再次调用生成模型；副本或补丁被改动时会拒绝。每次重试前归档上次的失败与检查，保留生成用量，记录当前验收宿主和包管理器版本。宿主环境与基线不同时会提示条件差异，缺少版本或耗时不会填成零。当前验收的耗时不包含历史空闲时间。

重新验收也占用运行名额，可单独停止，已完成的另一版继续保留。重启后仍可对保留且通过完整性检查的候选重新验收；已选择、采用、清理或锁文件不一致的结果不能这样重试。锁文件失败需要修正后开始新的比较，冻结安装不会被自动放宽。单份记录最多归档 100 次重试。

模型也可以自己调用 `agent_compare_start` 工具（参数：`task`，可选 `time_limit_minutes`），对话里显示同样的 A|B 卡片。
