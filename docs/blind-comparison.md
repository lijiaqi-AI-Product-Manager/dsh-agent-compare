# 盲选与揭晓 / Blind comparison

选择前，A、B 保留真实页面、运行阶段、耗时、共同验收结果、可否采用及执行边界。模型与策略、用量、改动规模、文件列表、工具名称与目标、候选自己的说明和详细日志在揭晓后显示。完整记录始终保存在本地。

安装失败时仍可看到失败分类、错误代码和恢复建议，也可对原候选重新验收。两版都无法体验时，可选择「两版都不采用并揭晓」查看详情；此操作不清理保留的代码。选择后的验收重试不会重新隐藏已揭晓的信息。

揭晓后、尚未采用或另存分支之前，可以「改选」另一版已完成的结果（例如盲选的那一版没有通过共同验收）。记录同时保留最初的盲选结果，揭晓说明会注明“揭晓后改选”。已经有采用记录的比较不能改选。

没有可用结果、两版都没选或选中的一版未通过验收时，可在同一张卡片里点「再比较一次」：用同一条需求在本对话中开始新的比较，并可先选更长的每版上限（上次因时长截断时，默认建议下一档）。原来的比较和记录保持不变；示例比较会新建一个示例仓库。

应用自身的文字和行为也可能透露来源。盲选减少标签造成的先入为主，不是匿名性保证，也不能把单次偏好推成模型排名。

Before selection, A/B retain their actual apps, stage, elapsed time, shared check outcomes, adoption eligibility and execution boundaries. Model/strategy identities, usage, change scale, file lists, detailed tool activity, candidate prose and raw logs appear after reveal. Full local records are preserved.

Installation failures retain their category, error code and recovery advice, and the original candidate can be reverified. When neither app runs, explicitly rejecting both reveals details without cleaning retained code. Later verification retries keep previously revealed information visible.

After the reveal and before any adoption or branch, the user can **pick the other finished version instead**, for example when the blind pick failed the shared checks. The record keeps the original blind pick, and the reveal summary marks the change. A comparison with an adoption record cannot be re-picked.

When no result is usable, neither version was picked, or the pick failed the checks, **Compare again** starts a new comparison of the same requirement in the same conversation, optionally with a longer time limit (the next longer limit is suggested when generation ran out of time). The earlier comparison and its record stay unchanged; an example comparison creates a fresh example repository.

An app's own content and behavior may reveal its source. Blind comparison reduces label bias; it does not guarantee anonymity or turn one preference into a model ranking.
