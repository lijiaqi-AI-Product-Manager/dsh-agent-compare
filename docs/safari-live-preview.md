# Safari 实时比较

[English](safari-live-preview.en.md)

适用于 macOS 上的本地 DSH Web 和 Safari。桌面版继续使用其自身浏览器环境；远程服务器、共享后端、登录与数据库不在当前前端比较范围内。

## 第一次使用

1. 在主对话点 A|B，展开设置，点「启用 Safari 实时比较」。需求草稿和已有记录保留，此时不会生成应用。
2. 阅读配置说明，再点「继续并请求系统授权」。管理员验证在 macOS 系统窗口完成；插件不读取或保存密码。可以取消。
3. 显示已就绪后，再明确发送需求或点内置示例。两版在独立地址实际运行，可以直接操作。需要第一方 Cookie 或存储时，点候选右上角的打开按钮，在真实标签页继续体验。

Safari 仍可能限制嵌入页面的 Cookie；直接标签页与嵌入页面的存储上下文也可能不同。该区别会在比较页面提示，不能把被浏览器阻止的存储写入记为通过。

## 系统配置的范围

每次启用添加一批 64 个随机、专用的 IPv4 回环地址，仅供本机预览。它们随系统重启释放；用完或重启后，界面会要求再次明确启用。不会修改 DNS、证书、防火墙或永久启动项，也不会删除既有地址。

地址计划在系统操作前写入私有记录。只有命令回执与实际系统地址都确认的条目才可分配；配置部分失败、取消或回执丢失时，保留未确认记录，不猜测归属。已使用地址不会分配给另一次预览，包括重新打开原候选，避免继承旧页面状态。

## 历史与恢复

历史中的旧 localhost 预览不会继续嵌入 Safari。启用后，点「用独立地址打开 A/B」重新运行原候选，无需重新生成；源码必须仍与封存版本一致。原进程只在归属可证明时停止，另一版保持运行。重新打开会改变浏览器地址，页面内的临时状态不保留；任务、选择、检查记录、补丁及截图继续保留。

如果取消系统授权，比较不会自动开始，也不会自动再次弹出授权。检查环境后可明确重试。出现地址记录损坏或无法确认进程归属时保留原数据并提示处理，不重置记录或扩大权限。

## 验证范围

[CI](https://github.com/lijiaqi-AI-Product-Manager/dsh-agent-compare/actions/workflows/ci.yml)分别检查当前原生 Safari、Playwright WebKit 和实际 DSH SDK。原生 Safari 记录应用版本，而非把 WebKit 引擎版本当作浏览器版本。检查包括双预览输入、语言切换保留文档、第一方 Cookie/存储分离、父级 Cookie 不进入预览、精确地址绑定、重启后的地址归属与清理。

系统地址测试只在一次性 macOS runner 中使用其明确的管理员授权；不会自动操作维护者电脑上的授权窗口。这些固定应用与受控运行检查不代表外部模型生成质量或耗时测量。

原生视觉验收使用标准 WebDriver 元素截图，直接检查应用内容的真实像素，并与同一会话的输入、文档身份和存储检查绑定。Safari 27.2 在当前 ARM runner 中的整窗捕获曾返回灰白空图，而元素捕获正确呈现应用；整窗结果仍单独保存并标明是否可用，不计作成功截图，也不替换成其它浏览器的图片。
